The WMS-tier owner of forward pick-face replenishment in the warehouse-systems
platform (ADR 0001, ADR 0002). It watches the stock level of every forward
pick face against an explicit **min/max policy** per site and SKU, and when
the projected level reaches the minimum it raises a **replenishment request**:
move a quantity of the SKU from a reserve bin to the forward bin, never more
than the policy maximum. Policy `MIN_MAX` is the only v1 policy; the source
bin policy is `fullest-reserve-bin-v1` (the reserve bin of the same site with
the most usable stock).

This service moves no stock and creates no floor work. A request is
published as `ReplenishmentRequested`; wes-work-planning plans it as
`REPLENISH` work, fulfillment-execution runs it with an operator and
inventory-storage records the relocation (reason `REPLENISHMENT`). The
resulting `StockRelocated` comes back and completes the request. A request is
cancelled when the operator says so, when a newer approved slot plan no longer
assigns the SKU to that forward bin, or when its policy is removed.

Stock levels, forward assignments and locations are read from local copies fed
by events (ADR 0003); this API never calls a sibling context. Events are
published as CloudEvents on `warehouse.pick-face-replenishment.events` through
a transactional outbox (see `apis/asyncapi.yaml`).

Errors are RFC 7807 problem documents with
`type = https://errors.pick-face-replenishment.warehouse-systems.dev/<slug>`.
There is no authentication layer (fleet decision 2026-09-11).
